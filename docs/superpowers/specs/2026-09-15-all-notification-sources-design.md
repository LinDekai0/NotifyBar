# NotifyBar 通用 Windows 通知来源

用户已批准：从 QQ/微信专用筛选扩展为用户选择 Windows 通知应用；不考虑微信自带弹窗。继续使用 Subagent-Driven Development，提交说明用中文。用户授权完整版编译、MSIX 安装和本机通知接收验证，也接受需本人操作时提供步骤。

## 行为

- 设置中列出系统通知里发现的应用，提供搜索、逐应用开关、全选/取消选择、刷新。新安装默认关闭所有来源；旧配置迁移保留 QQ/微信选择。
- 精确 AppUserModelId 是选择、队列二次筛选和跨来源去重的身份，显示名只用于展示。未知/空标识不能获得默认放行。
- 启动和权限恢复的当前快照用于发现应用，不展示旧消息。来源发现必须发生在旧消息过滤之前。用户启用来源之后，仅后续新消息显示。
- 应用列表只存 ID、名称及选择，不存正文、通知标题或个人消息内容。刷新不能覆盖未保存的勾选，保存失败要明确提示。
- 无来源时引导：开启目标软件 Windows 通知并产生一条通知，再刷新。列表不是所有已安装软件的承诺。
- 覆盖层显示实际应用名称；较长名称限制宽度，保留消息可读空间。测试弹幕独立于来源选择。
- 保留每秒 3 条、最多同时 5 条、暂停保留最近 10 条、队列上限 100、不激活和鼠标穿透。
- NotifyBar 自己的错误通知不得造成弹幕反馈循环。无包身份/拒绝权限仍可使用显示测试。

## 发布和验收

使用 .NET 8 WPF 和已有 Windows TFM 的 WinRT 投影；内部 NotificationBarrage 名称/配置路径不改，用户界面中文、产品名 NotifyBar。不引入聊天窗口读取、游戏注入、上传或发消息功能。

恢复官方 NuGet，执行 Release/xUnit/离线行为检查、预览和完整版构建。用 MakeAppx 生成自包含 x64 MSIX。开发签名仅针对本项目，私钥和证书放忽略目录，不关闭签名验证、不导入到根证书库。安装失败时记录实际 Windows 错误并提供可执行步骤。

系统权限由用户在可见窗口授予；接收检查不输出真实消息正文。可用本机生成的 Windows Toast 验证操作系统接收链路，明确区分这与 Telegram/QQ 等外部应用发来的真实消息验收。不向其他人发消息。最终报告分别列出编译、包签名、安装、权限、系统 Toast 和外部应用消息的验证结果。
