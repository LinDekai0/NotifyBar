# Windows QQ/微信通知弹幕桌面应用设计

## 目标

在 Windows 上运行一个常驻托盘的桌面应用。当 QQ 或微信产生 Windows 桌面通知时，应用读取通知内容，并在游戏画面上方显示一条从右向左移动、随后淡出的弹幕。应用不连接 QQ/微信账号、不读取聊天窗口、不上传消息内容，也不提供回复功能。

首版支持 Windows 10 1903 及以上版本和 Windows 11，目标框架为 .NET 8 WPF。应用放在当前仓库的新目录 `notification-barrage/` 中，与现有股票预测网页项目隔离。

## 范围

首版包含：

- 通过 Windows UserNotificationListener 读取新通知。
- 默认识别并显示 QQ、微信来源的通知。
- 单屏透明置顶覆盖层，弹幕从右向左移动并淡出。
- 托盘常驻、暂停/恢复、测试弹幕、打开设置和退出。
- 设置来源开关、速度、字体大小、透明度、显示位置、最大正文长度和开机启动。
- 消息去重、队列、并发显示上限和接收限流。
- 本地 JSON 设置和本地错误日志。
- 权限缺失、通知字段缺失和监听器初始化失败时的可操作提示与退避重试。

首版不包含：

- 多屏独立布局。
- 历史消息面板或消息搜索。
- 云同步、账号登录、网络上传。
- 通过 QQ/微信发送或回复消息。
- 读取关闭通知后的聊天窗口内容。

## 用户流程

1. 用户启动应用，应用进入系统托盘，不打开主窗口。
2. 首次启动时，应用检查通知访问权限。未授权时打开设置引导，告诉用户如何授予权限，并在托盘菜单保留“重新检查权限”。
3. 用户可以在设置窗口调整来源、位置、动画速度、字体、透明度和最大正文长度，并保存到本地。
4. 用户点击“测试弹幕”确认覆盖层在当前游戏和显示器上可见。
5. QQ/微信产生新 Windows 通知后，监听器提取来源、标题、正文和通知 ID，经过过滤、去重和限流后加入队列。
6. 覆盖层取出队列消息并显示；展示结束后移除该消息，继续处理下一条。
7. 用户可从托盘暂停展示、恢复展示或退出应用。暂停期间仍可接收通知，但恢复时只保留最近 10 条待展示消息。

## 架构

### AppHost

负责单实例启动、WPF 生命周期、托盘图标、全局异常捕获、设置加载和服务协调。启动失败或关键服务异常时写入本地日志，并通过托盘通知给出简短原因。

### NotificationListener

封装 Windows UserNotificationListener。负责申请/检查访问权限、订阅新通知事件、把系统通知映射为内部 `IncomingNotification`，并在监听器不可用时按退避间隔重试。该模块不负责来源筛选和 UI。

`IncomingNotification` 至少包含：通知 ID、应用标识/显示名、标题、正文、接收时间。缺少正文且标题也为空的通知直接丢弃并记录调试日志。

### MessageFilter

根据设置中的来源开关筛选消息。初始来源匹配使用 Windows 通知的应用显示名和已知包标识，默认覆盖 QQ 和微信；匹配规则集中在配置中，便于后续修正不同安装版本的标识。该模块还负责正文截断、规范化空白和生成去重键。

### BarrageQueue

维护消息先进先出队列和正在展示的消息数量。使用通知 ID 去重；当 ID 不稳定时，使用来源、标题、正文和短时间窗口组成的哈希去重。接收速率限制为每秒最多 3 条，最多同时展示 5 条。暂停时最多保留最近 10 条，恢复时丢弃更早积压。

### OverlayWindow

使用无边框、透明、置顶窗口承载弹幕条。窗口默认位于主屏幕底部约 15% 区域，支持顶部/中部/底部和垂直偏移。弹幕条包含来源色块、标题和正文，正文按最大长度截断。窗口及弹幕元素启用鼠标穿透，避免拦截游戏输入；窗口不激活，不抢占焦点。动画默认从右侧进入、向左移动并淡出，速度和透明度来自设置。

### SettingsWindow

提供来源开关、位置、垂直偏移、速度、字体大小、透明度、最大正文长度和开机启动选项。保存目标为 `%AppData%\\NotificationBarrage\\settings.json`，写入采用临时文件替换，避免应用异常时损坏配置。设置变更通过内存配置对象通知监听器、队列和覆盖层。

### Logging

本地日志写入 `%AppData%\\NotificationBarrage\\logs\\`，按日期分文件并限制单文件大小。日志只记录运行状态、错误和必要的诊断元数据，不记录完整消息正文，避免在日志中持久化聊天内容。

## 数据流

```text
Windows 通知
    -> NotificationListener
    -> MessageFilter（来源、空白、长度）
    -> BarrageQueue（去重、限流、暂停策略）
    -> OverlayWindow（动画和淡出）
```

托盘和设置窗口只通过 `AppHost` 访问这些服务，不直接操作系统通知对象。测试弹幕绕过监听器，直接走队列和覆盖层，以验证显示链路。

## 权限和错误处理

- 未授予通知访问权限：托盘显示一次引导通知，设置窗口提供打开 Windows 隐私/通知设置的入口；监听器定时重试但不循环弹窗。
- 系统版本或 API 不支持：应用保持托盘运行，禁用监听功能并显示明确错误；测试弹幕仍可用于验证覆盖层。
- 监听器初始化或事件订阅失败：记录错误，按递增退避间隔重试。
- 通知字段缺失：标题和正文都为空则跳过；仅有一项时显示现有内容。
- 覆盖层动画异常：移除异常消息，记录错误，继续处理队列。
- 配置文件损坏：备份损坏文件，加载默认设置，并通过托盘提示用户。

## 安全和隐私边界

应用只处理 Windows 通知访问权限允许读取的本机通知。消息内容只在内存中流转到覆盖层，不上传、不写入日志、不发送回 QQ/微信。设置文件只保存显示偏好和来源开关，不保存账号或凭据。

## 验证策略

- 单元验证：来源匹配、正文截断、去重键、限流、暂停恢复和配置读写。
- Windows 集成验证：权限状态读取、通知事件映射、托盘菜单、鼠标穿透和窗口置顶。
- 手工验收：使用“测试弹幕”检查位置和动画；分别从 QQ、微信发送一条通知，确认消息只显示一次；关闭来源开关确认被过滤；暂停后恢复确认最多显示最近 10 条。
- 失败路径验收：拒绝权限、删除/损坏配置文件、模拟监听器异常，确认应用仍可启动且有可操作提示。

## 后续可扩展点

将通知来源匹配、队列策略和覆盖层参数隔离后，后续可以增加 Telegram、钉钉等来源、多屏布局或按游戏保存配置；这些不进入首版实现范围。
